AI Study Pal (working title)

Technical spec. Status: approved. Markdown (spec.md) is the canonical version.

How it works, in plain language

A website that opens on a phone like an app. Vercel serves the screens and runs small server functions that hold the AI key. Supabase is a spreadsheet in the cloud that remembers courses, units, questions, lessons and scores. Nemotron is the AI that reads the unit, writes questions, marks typed answers and writes lessons. No sign-in: each phone makes a random secret ID. The PDF is read on the phone, and only its text goes to Supabase.

The pieces

Only text travels from the phone. The AI key and the database key stay on Vercel.

One student's journey through the pieces

1. Open the link

The phone makes or reads its secret ID and asks Vercel for its units. Nothing yet: the empty screen with a plus button.

PRD: Home and navigation

2. Add a unit

The phone reads the PDF text itself. The text goes to POST /api/units.

PRD: Adding a course and unit

3. The AI prepares the unit

Nemotron splits the text into topics and writes baseline and final questions on the same key parts. Saved to Supabase.

PRD: Baseline mock test

4. Baseline test

Five questions per topic. POST /api/mark marks the five answers in one AI call. The score is saved as an attempt.

PRD: Baseline mock test

5. Results and style

Strong and weak topics come from saved scores. The student picks a style and where to start.

PRD: Teaching styles and starting point

6. Lesson

POST /api/lesson returns steps with a drawing each, saved so it's never written twice.

PRD: Lesson

7. Topic check

The same marking call, saved as an attempt.

PRD: Topic check

8. Final test and before-and-after

Final questions (same parts, new wording) are marked. The screen compares baseline and final scores.

Stack

What we're using
  • Next.js + TypeScript + Tailwind: screens and server functions in one project
  • Supabase: the cloud database you chose
  • Nemotron via NVIDIA's OpenAI-compatible endpoint: the AI you chose
  • pdf.js: reads PDF text on the phone
  • Vercel: hosting you chose

Check early: exact model name, free limits (reported ~1,000 credits, 40 requests/min), pdf.js on a phone, quality of AI-drawn diagrams.

Components, tied to the PRD

Home and Navbar, Pomodoro
  • Burger (courses), pomodoro and avatar; empty state or two-column cards
  • Files: app/page.tsx, components/Navbar.tsx, UnitCard.tsx, Pomodoro.tsx
Add course and unit, unit analysis
  • Phone reads the PDF; function asks the AI for topics and questions
  • Files: app/add/page.tsx, lib/pdf.ts, app/api/units/route.ts
Tests, results, lessons, comparison
  • One-topic-at-a-time test view with a progress box
  • One marking call per topic; lessons cached by topic and style
  • Files: TestView.tsx, Results.tsx, LessonView.tsx, DiagramSvg.tsx, ScoreCompare.tsx, api/mark, api/lesson

Data model

Four tables
  • students: the secret ID
  • courses: name, level
  • units: material text, style, current topic, and topics (questions and lessons inside)
  • attempts: baseline, check or final score per topic

Clearing the browser's data loses the ID. Accepted for the hackathon; accounts fix it later.

If it breaks

Three likely failures
  • PDF has no readable text: plain message; paste text instead
  • AI slow or out of credits: one retry, then a friendly "try again in a minute"; saved work stays
  • Messy AI output or broken drawing: one retry; otherwise the step shows as a text card

Simplified on purpose

What we kept small, and why
  • Random device ID, not accounts
  • Extracted text, not stored PDFs or a phone folder
  • AI-drawn SVG diagrams, not generated images
  • Four tables, one demo unit of about three topics
