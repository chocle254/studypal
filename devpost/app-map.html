Study Pal

Test first, teach only the gaps, then show the before-and-after. A phone-first study app built for Devpost's Build With AI: Basics.

The main pieces

Phone screens

Next.js pages and components in app/ and components/. PDF text is read on the phone (lib/pdf.ts).

Server routes

Small functions in app/api/ that hold the keys, call the AI and save results. Answers never go to the phone.

The AI

Groq (or NVIDIA) through lib/nvidia.ts. All instructions to it live in lib/prompts.ts.

Storage

Supabase tables students, courses, units, attempts via lib/supabase.ts.

A 3-stop route through the code

Reference route. Open each file on GitHub (or in an editor) and search for the anchor.

  1. The screen asks for a lesson

    components/LessonView.tsx → search fetchLesson

    When you tap Learn, this sends the topic number and your teaching style to the server and shows the “Writing your lesson…” screen with the topic's key parts while it waits.

  2. The server finds your pages and asks the AI

    app/api/lesson/route.ts → search export async function POST, then sourceFor in lib/parts.ts and lessonPrompt in lib/prompts.ts

    If the lesson is already saved, it's returned straight away. Otherwise sourceFor cuts out the part of your PDF about this topic, lessonPrompt tells the AI what sections to write and which mistakes from your first test to clear up, and askJson (lib/nvidia.ts) retries if the reply isn't valid JSON. The result is saved with updateUnit.

  3. The phone draws it

    lib/diagram.ts → cleanDiagram, then components/Diagram.tsx and components/LessonText.tsx

    The AI only supplies words in one of four shapes (flow, cycle, compare, parts). cleanDiagram drops anything that doesn't fit; Diagram draws it in the app's colours; LessonText turns numbered points into real lists.

    What the AI sends for a flowchart 
    { "kind": "flow",
  "steps": ["Collect data", "Train logistic", "Validate", "Score new"] }

A practice to reuse

Give the AI the real material, ask it for structured data, and let your own code do the drawing.

The first lessons only received a 120-word summary of each topic, and the AI drew its own SVG pictures. Trying them on a phone with a real PDF showed both problems at once: shallow text and meaningless images. The fix was two changes you can see in the route above. sourceFor now passes the student's actual pages, and the AI returns a small JSON shape that cleanDiagram checks and Diagram draws (see devpost/checklist.md → Revisions).

On another project: when AI output looks thin, check what it was given before blaming the model. When the AI's output has to look right every time, have it fill a fixed shape your code validates and renders. Then try each slice with real content on the real device before moving on.

Run it again

Live: open the Vercel link on your phone. Health check: /api/health.

Locally: npm install, then npm run dev, and open http://localhost:3000. Without keys it uses a local file database and a labelled stand-in AI.
